# 旅游城市天气预报及观星条件预报软件 — 设计方案

## Context（背景与目标）

基于已验证的安吉天荒坪三源集成预报文档，开发一款面向旅游/观星目的地的 Web 应用：
- **后端** Python + FastAPI，聚合多个免费气象/天文 API
- **前端** 原生 HTML/CSS/JS + Chart.js，无需构建步骤
- 复刻文档全部能力：实况、预警、7天预报、逐小时、多模型集成、观星评分、月相、历史同期、天气系统分析
- 支持多城市预设 + 自定义坐标，安吉天荒坪为默认

**已验证的免费数据源（均无需 API Key）**：

| 数据源 | 端点 | 能力 | 限制 |
|:---|:---|:---|:---|
| CMA 中央气象台 | `weather.cma.cn/api/{now,weather,hourly}/{stationid}` | 实况+气象预警+7天+逐小时(含云量/能见度) | 仅中国站点，需站点ID |
| Open-Meteo ECMWF | `api.open-meteo.com/v1/ecmwf` | 15天预报，9km，支持 elevation 地形降尺度 | 非商用 <1万次/天 |
| Open-Meteo GFS | `api.open-meteo.com/v1/gfs` | 16天预报，模型对比 | 同上 |
| Open-Meteo Archive | `archive-api.open-meteo.com/v1/archive` | 历史同期(可回溯1940) | 同上 |
| Open-Meteo Astronomy | forecast API 的 daily 变量 | 日出日落/月出月落/月相 | 同上 |

## 一、技术栈

| 层 | 选型 | 理由 |
|:---|:---|:---|
| 后端框架 | FastAPI + uvicorn | async 并发抓取三源，自动 OpenAPI 文档 |
| HTTP 客户端 | httpx (async) | 原生异步，超时/重试控制 |
| 数据校验 | Pydantic v2 | FastAPI 内置，响应模型 |
| 前端 | HTML5 + CSS3 + 原生 ES6 | 无构建步骤，符合"html前端+基本动态互动" |
| 图表 | Chart.js (CDN) | 温度曲线/云量/气压趋势 |
| 缓存 | 文件 JSON + TTL | 降低 API 调用，stale-while-revalidate |
| 打包 | requirements.txt | 依赖清单 |

## 四、后端 API 端点

| 方法 | 路径 | 说明 | 数据源 |
|:---|:---|:---|:---|
| GET | `/api/cities` | 预设城市列表 | config |
| GET | `/api/weather/{city_id}/now` | 实况+气象预警 | CMA now(+Open-Meteo current 兜底) |
| GET | `/api/weather/{city_id}/forecast` | 7天预报(含集成) | CMA daily + Open-Meteo |
| GET | `/api/weather/{city_id}/hourly?date=` | 指定日逐小时 | CMA hourly / Open-Meteo hourly |
| GET | `/api/weather/{city_id}/multimodel?date=` | ECMWF vs GFS + 集成 + 分歧度 | Open-Meteo ECMWF+GFS |
| GET | `/api/stargazing/{city_id}?date=` | 观星评分时间轴18:00-05:00+最佳窗口 | 综合 |
| GET | `/api/astronomy/{city_id}?date=` | 月相/日出日落/月出月落 | Open-Meteo daily |
| GET | `/api/historical/{city_id}?month_day=08-15` | 近3年同期比对 | Open-Meteo Archive |
| GET | `/api/analysis/{city_id}?date=` | 气压趋势+天气系统识别 | Open-Meteo ECMWF |

所有端点返回统一 JSON：`{ "city": {...}, "data": {...}, "meta": {"sources":[...], "updated_at":..., "confidence":...} }`

## 五、核心算法

### 5.1 观星评分（stargazing.py，0-100）

| 维度 | 权重 | 评分公式 |
|:---|:---:|:---|
| 云量 cloud_cover | 35% | `100 - cloud_cover%` |
| 月相 moon | 25% | 月在地平线下→100；否则 `100 - 照亮%` |
| 能见度 visibility | 15% | ≥20km→100，<2km→0，线性插值 |
| 湿度 humidity | 15% | `100 - max(0, humidity-50)`（越干越好） |
| 风速+阵风 gust | 10% | `100 - max(0, gust_kmh-20)*2` |

**评级**：≥70 🟢优 ｜ 50-69 🟡良 ｜ 30-49 🟠中 ｜ <30 🔴差
**最佳窗口**：取评分最高的小时；若连续≥2小时≥50则推荐为"可观测时段"。

### 5.2 多模型集成（ensemble.py）

- 逐小时对齐 ECMWF 与 GFS（按ISO时间戳）
- 集成值 = 简单平均（温度/云量/风速）或加权（降水取较小值偏保守）
- 分歧度 = `|ECMWF - GFS|` 的日均，分"小/中/大"三档

### 5.3 海拔订正（elevation.py）

- 优先用 Open-Meteo `elevation=` 参数直接获取地形降尺度结果
- 对 CMA 数据（站点海拔）手动递减率订正：`T_adj = T - 6.5°C/1000m × (目标海拔 - 站点海拔)`

### 5.4 天气系统识别（typhoon.py）

- 取目标日前后7天 ECMWF 海平面气压序列
- 识别气压谷（<980 hPa 且24h降幅>10 hPa）→ 标记台风/强系统
- 计算阵风峰值与目标日差值，判定影响是否结束

## 六、缓存策略（cache.py）

- 文件路径：`cache/{source}_{city}_{endpoint}_{date}.json`
- TTL：CMA now=10min ｜ forecast/hourly=1h ｜ Open-Meteo=1h ｜ historical=7天 ｜ astronomy=24h
- stale-while-revalidate：上游失败时返回过期缓存（标记 `stale:true`），避免界面空白

## 七、前端设计（static/）

**单页布局**（顶部城市选择器 + 内容分区，切换城市/日期动态重载）：

1. **顶栏**：城市下拉 + 自定义经纬度输入 + 日期选择 + 刷新按钮
2. **实况卡**：气温/体感/气压/湿度/风 + 气象预警徽章（黄/橙/红）
3. **7天预报条**：日期卡片（高低温、天气图标、风力）
4. **逐小时图**：Chart.js 双轴——温度折线 + 云量面积图 + 风速柱
5. **多模型对比**：ECMWF/GFS/集成表格 + 分歧度指示条
6. **观星时间轴**：18:00-05:00 逐时评分条 + 最佳窗口高亮 + 月相图标
7. **天文信息**：月相可视化(照亮%) + 日出日落/月出月落时间轴
8. **历史同期**：近3年柱状对比图
9. **天气系统分析**：气压趋势折线 + 系统识别结论

**动态交互**：城市切换→并发拉取所有端点→分区渲染；日期切换→重载逐小时/观星/分析；hover tooltip；每10分钟自动刷新实况。

## 九、验证方式

1. **启动**：`pip install -r requirements.txt` → `uvicorn app.main:app --reload`
2. **API 自测**：访问 `http://localhost:8000/docs`（FastAPI 自动文档）逐个测试端点
3. **数据真实性**：`GET /api/weather/anji/now` 应返回与 `weather.cma.cn/api/now/58446` 一致的实况
4. **观星验证**：`GET /api/stargazing/anji?date=2026-08-15` 结果应与文档第六节评分趋势吻合（21:00为最佳窗口）
5. **前端**：浏览器打开 `http://localhost:8000`，切换城市/日期，确认各分区动态渲染、图表正常
6. **缓存**：二次请求相同端点响应时间应显著下降，`cache/` 下生成 JSON 文件
7. **降级**：断网时返回过期缓存（`stale:true`）而非报错
